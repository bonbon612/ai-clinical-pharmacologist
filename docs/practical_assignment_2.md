# Практическое задание 2. MCP в системе «ИИ клинический фармаколог»

## Цель

Одна предметная система подключает три MCP-провайдера через разные транспорты. Все действия инициируются стандартными методами `tools/list` и `tools/call`. LLM для работы не требуется.

## Реализация

### 1. Локальный провайдер stdio

`clinical_mcp.server` создан на официальном MCP Python SDK 2.x. Протокол JSON-RPC 2.0 передаётся через stdin/stdout; журналы направлены в stderr. Аннотации типов и `pydantic.Field` формируют JSON Schema и отклоняют значения вне допустимых диапазонов.

Доступно шесть инструментов: `calculate_bmi`, `calculate_egfr_2021`, `calculate_cockcroft_gault`, `calculate_cha2ds2_vasc`, `calculate_gcs`, `list_calculators`.

### 2. Сетевой провайдер

`clinical_mcp.network_server` по умолчанию запускает stateless Streamable HTTP на порту 8000. Режим `--transport sse` создаёт `/sse` и `/messages` для совместимости. Оба транспорта используют тот же набор инструментов и одну реализацию проверки входных данных.

Клиент асинхронный. На вызов установлен предел 12 секунд и до трёх попыток для временного сетевого сбоя. `sanitizer.py` приводит типы, применяет значения по умолчанию и ограничивает числа по JSON Schema.

### 3. Локальный провайдер доказательств

`POST /api/mcp` реализован вместе с web-приложением и доступен локально по адресу `http://127.0.0.1:4173/api/mcp`. Он предоставляет поиск RxNorm, получение инструкций DailyMed и полный разбор терапии. Запросы к источникам имеют тайм-аут 15 секунд, повтор при `429`/`5xx` и кэш на 5 минут.

### 4. Web-интерфейс

`streamlit_app.py` позволяет выбрать источник, отфильтровать инструменты и построить форму по `inputSchema`. Результат показывает значение, риск, компоненты и ссылку на источник. Инспектор выводит полный JSON-RPC запрос и ответ.

## Ответы на теоретические вопросы

**Что даёт MCP?** Единый контракт обнаружения и вызова инструментов. Интерфейс не знает реализацию калькулятора или источника и работает с их схемами.

**Чем отличаются транспорты?** stdio запускает дочерний локальный процесс. Streamable HTTP подходит для сетевого сервиса и нескольких клиентов. SSE оставлен для совместимости со старыми хостами. Провайдер RxNorm/DailyMed работает по локальному HTTP-адресу.

**Зачем JSON Schema?** Она описывает типы, обязательные поля, перечисления и диапазоны. Сервер отклоняет ошибочный вызов до выполнения медицинского расчёта, а интерфейс строит по схеме корректные поля.

**Как обработаны ошибки?** Клиент ограничивает время ожидания, повторяет временный сетевой сбой и показывает сообщение инструмента. Локальный провайдер возвращает ошибку инструмента в `isError`, не маскируя её под успешный результат.

**Почему приложение работает без LLM?** Выбор инструмента делает пользователь, расчёты выполняют формулы, а поиск обращается к структурированным источникам. Это обеспечивает воспроизводимость демонстрации.

**Как защищаются клинические данные?** Приложение не требует ФИО и других идентификаторов, проверяет диапазоны, ограничивает длину ввода и не сохраняет пользовательские запросы.

## Проверка

- 11 Node-тестов существующей мультиагентной системы и локального MCP;
- 8 тестов формул и sanitizer;
- 3 интеграционных теста MCP: каталог, успешный вызов и отклонение неверных аргументов;
- ручная проверка stdio, Streamable HTTP и запуска SSE.
